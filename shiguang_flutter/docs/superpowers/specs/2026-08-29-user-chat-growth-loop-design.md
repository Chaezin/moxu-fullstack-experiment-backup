# 用户聊天持久化与自动成长卡片设计

## 目标

将当前浏览器本地演示数据升级为真实的多用户系统：聊天记录绑定登录用户并长期保存；系统在每轮完整对话后异步分析成长证据，达到阈值时自动生成成长卡片和技能点。

## 已确认的产品规则

- 每轮完整对话结束后异步分析，但不保证每轮都生成卡片。
- 只有出现具体且有新增价值的成长证据时才生成卡片。
- 每日执行一次补偿汇总，合并跨多轮证据并补足遗漏。
- 卡片生成后直接入库，标注“AI 自动整理”，允许修改和删除。
- 原“收入卡片”改为“查看成长卡片”。
- 删除聊天后保留卡片，但移除聊天原文引用；卡片可单独删除。

## 总体架构

采用模块化单体后端加独立后台任务：

1. Flutter/Web 前端只负责交互和短期缓存。
2. FastAPI 负责认证、用户隔离、会话、消息、技能与卡片 API。
3. PostgreSQL 是正式数据的唯一权威来源；本地开发允许 SQLite 运行测试。
4. 消息写入成功后通过事务事件创建分析任务。
5. 后台 Worker 提取技能证据、去重并按阈值生成卡片。
6. 前端通过事件流或短轮询接收卡片和分析状态更新。

聊天保存和 AI 分析解耦。AI 服务不可用时，聊天仍然保存，任务进入重试队列，不阻塞用户继续对话。

## 数据模型

- `users`：账号、密码摘要、状态、创建时间。
- `refresh_tokens`：刷新令牌摘要、用户、过期和撤销时间。
- `conversations`：所属用户、标题、状态、最后消息时间、软删除时间。
- `messages`：所属用户与会话、角色、内容、顺序号、客户端幂等 ID、创建时间。
- `analysis_jobs`：用户、触发消息、任务状态、重试次数、幂等键和错误摘要。
- `user_skills`：用户技能标准名、展示名、分类、置信度和版本。
- `skill_evidence`：技能、来源消息、证据摘要、评分；聊天删除后清空消息引用。
- `growth_cards`：用户、标题、摘要、生成来源、状态、生成时间和去重键。
- `growth_card_skills`：卡片与技能的多对多关系。
- `outbox_events`：保证消息提交和分析任务投递的一致性。

所有业务查询都从认证信息取得 `user_id`。客户端传入的用户 ID 不作为数据权限依据；数据库外键和唯一约束同时防止跨用户关联。

## 核心流程

### 登录与恢复

登录成功后返回短期访问令牌和可撤销刷新令牌。前端调用会话列表接口，再按需加载消息、技能与卡片。退出登录时清除本地缓存；重新登录后以服务端数据恢复。

### 发送消息

1. 后端验证会话属于当前用户。
2. 使用 `client_message_id` 幂等保存用户消息。
3. 保存或流式返回助手消息。
4. 在同一事务写入 outbox 事件。
5. 后台任务消费事件并开始分析。

重复提交相同 `client_message_id` 时返回原消息，不产生重复聊天和分析任务。

### 技能与卡片分析

Worker 只读取当前用户在上次分析游标后的新消息，要求 AI 返回符合固定 JSON Schema 的结构化结果。系统完成技能名称归一、证据去重、置信度合并和卡片阈值判断。

首版阈值规则：证据必须描述具体行动或结果；相对已有证据有明显新增；同一事件不得重复生成；单日卡片数量受限。规则参数保存在后端配置中，后续可调整而无需改前端。

### 删除

聊天采用软删除，默认不再返回消息。相关技能证据保留摘要和评分，但清空原消息引用及可回显原文；已经生成的卡片继续存在。用户删除卡片时，卡片与技能关联一起删除，但不删除原聊天。

## API 边界

- `POST /api/v1/auth/login`
- `POST /api/v1/auth/refresh`
- `POST /api/v1/auth/logout`
- `GET /api/v1/me`
- `GET/POST /api/v1/conversations`
- `GET/PATCH/DELETE /api/v1/conversations/{id}`
- `GET/POST /api/v1/conversations/{id}/messages`
- `GET /api/v1/skills`
- `PATCH/DELETE /api/v1/skills/{id}`
- `GET /api/v1/cards`
- `PATCH/DELETE /api/v1/cards/{id}`
- `GET /api/v1/events`（SSE；不可用时前端降级短轮询）

响应沿用当前前端已经使用的 `/api/v1` 形状，降低页面切换成本。

## 前端改造

- 登录后先恢复账号资料、会话、卡片与技能，再允许发消息。
- 当前会话 ID、消息列表和本地缓存均按登录用户隔离。
- 发送消息采用乐观显示和 `client_message_id`，失败时可安全重试。
- 显示“正在整理成长记录”“已生成新卡片”等非阻塞状态。
- 将“收入卡片”改为“查看成长卡片”，删除手动生成卡片逻辑。
- 卡片详情展示“AI 自动整理”，支持编辑、删除及有限来源说明。

## 安全与可靠性

- 密码只保存强哈希；刷新令牌只保存摘要。
- 每个资源访问都验证当前用户所有权，测试覆盖跨用户读取和写入。
- 限制消息长度、请求频率和分析上下文大小。
- AI 输入视为不可信内容，使用结构化输出校验，拒绝越权指令和未知字段。
- 分析任务具备幂等键、指数退避、最大重试和失败记录。
- 日志不记录访问令牌、密码或完整私密聊天正文。

## 验收标准

- 用户退出并重新登录后，历史会话和消息完整恢复。
- 两个账号无法读取、修改或删除彼此数据。
- AI 分析失败时聊天不丢失，恢复后任务可重试且不重复生成。
- 达到阈值时自动生成卡片，无需点击按钮。
- 删除聊天后卡片仍存在，但无法再查看被删聊天原文。
- 前端现有语音输入与基础聊天界面测试保持通过。
