# 拾光语音转文字输入设计

## 状态

- 日期：2026-08-29
- 状态：已确认，等待实施计划
- 目标平台：Android、iOS、Windows；浏览器预览提供降级支持

## 目标

让用户在对话输入区点击语音按钮开始识别，再次点击停止，将中英文混合语音转为文字并追加到输入框已有内容后，随后自动发送。功能应复用现有消息发送流程，不保存或上传原始录音。

## 非目标

- 不实现持续后台监听或唤醒词。
- 单次语音输入面向短句和口述消息，目标时长不超过 60 秒。
- 不保存、回放或上传原始音频。
- 不在首版接入付费云端语音识别服务。
- 不改变现有文字输入、Enter 发送和发送按钮行为。
- 不保证不同系统对中英文混说具有完全一致的准确率。

## 现状

网页端已经包含语音按钮、波形动画、`state.listening` 状态、对话输入框和 `submitChatInput(input)` 发送函数。当前语音按钮只切换视觉状态，没有申请麦克风权限、调用语音识别或写入转写结果。

移动端使用 `webview_flutter` 加载 Flutter 资源；Windows 使用 `webview_flutter_windows` 加载指定网页。两个 WebView 当前都没有配置语音相关的原生桥接。

## 方案选择

采用“Flutter 原生识别为主，浏览器 Web Speech API 降级”的混合方案：

- Android、iOS、Windows 使用 `speech_to_text`，由 Flutter 统一管理权限和识别会话。
- 网页通过消息桥请求开始或停止，Flutter 将状态与识别文本回传网页。
- 独立浏览器预览没有 Flutter 桥接时，使用 Web Speech API。
- 如果当前运行环境不支持任何识别方式，按钮恢复为空闲并提示用户使用文字输入。

选择该方案是因为它不需要云端密钥和额外后端，能够覆盖目标 Flutter 平台，同时保留当前网页预览的可演示性。Windows 插件支持仍属 beta，必须通过真实 Windows 环境验收。

## 组件边界

### Flutter 语音控制器

新增独立的语音控制器，职责限定为：

- 初始化语音识别能力。
- 查询和申请麦克风、语音识别权限。
- 选择识别语言。
- 开始、停止和取消识别。
- 输出部分结果、最终结果、状态和结构化错误。
- 保证同一时刻只有一个会话。

控制器依赖一个可替换的识别服务接口，生产实现包装 `speech_to_text`，测试使用假实现。控制器不直接操作网页 DOM，也不发送聊天消息。

### WebView 桥接适配器

桥接适配器负责在网页消息与语音控制器之间转换：

- Android/iOS：使用 `webview_flutter` JavaScript Channel 接收网页请求，通过 JavaScript 事件回传结果。
- Windows：使用 WebView2 `webMessage` 接收网页请求，通过 `postWebMessage` 回传结果。
- 只接受允许的消息类型和字段，并校验当前页面来源。

### 网页语音协调器

网页端新增单一语音协调器，职责为：

- 检测 Flutter 桥接、Windows WebView2 桥接或 Web Speech API。
- 保存开始录音前输入框的原始文字。
- 处理状态、部分结果、最终结果和错误。
- 将原文字与识别文字安全合并。
- 在用户主动停止且获得可用结果后调用现有 `submitChatInput()`。

网页协调器不直接保存对话，也不复制现有 API 请求逻辑。

## 消息协议

网页发送给 Flutter：

- `voice.start`：包含会话 ID 和首选语言 `zh-CN`。
- `voice.stop`：包含当前会话 ID，表示用户主动结束并要求自动发送。
- `voice.cancel`：页面离开、组件销毁或异常时取消，不发送。

Flutter 回传网页：

- `voice.status`：`requesting`、`listening`、`stopping`、`idle`。
- `voice.partial`：当前会话的实时识别文本。
- `voice.final`：当前会话的最终识别文本。
- `voice.error`：稳定错误码和可展示的中文说明。

每条消息都携带会话 ID。网页忽略旧会话消息，防止迟到回调造成重复发送或覆盖新输入。

## 交互与数据流

1. 用户点击“说话”。
2. 网页记录输入框已有内容，创建唯一会话 ID，将状态设为 `requesting`。
3. Flutter 请求权限并初始化识别器。
4. 成功后进入 `listening`，按钮显示“停止”和动态波形。
5. 部分结果实时追加在原文字后，仅更新输入框，不发送。
6. 用户再次点击按钮，网页发送 `voice.stop`，状态变为 `stopping`，按钮暂时不可重复点击。
7. Flutter 停止识别并等待最终结果；网页最多等待 1.5 秒接收最后一段结果。
8. 网页使用最终结果；若等待窗口内没有最终结果，则使用当前最佳部分结果。转写追加到开始前的原文字，规范空格但不改写内容。
9. 合并结果非空时，只调用一次 `submitChatInput(input)` 自动发送。
10. 发送触发后清理会话状态并恢复按钮为空闲。

自动发送仅由用户第二次点击停止触发。系统自行超时、权限失败、页面退出或识别错误均不得自动发送。

## 中英文混合策略

- 首选识别语言为 `zh-CN`，允许系统识别器处理常见英文单词和短句。
- 若设备不提供 `zh-CN`，优先选择中文区域变体，其次回退到系统默认语言。
- 首版不在一句话中动态切换两个识别器，避免重复片段和顺序错乱。
- 如果后续真机数据显示混合识别准确率不能满足要求，再单独设计云端多语言 ASR，不在本次范围内增加音频上传。

## UI 状态

- `idle`：按钮文字“说话”，说明“按一下开始，再按一下结束”。
- `requesting`：按钮暂时禁用，说明“正在请求麦克风权限…”。
- `listening`：按钮文字“停止”，显示现有动态波形，说明“正在聆听，再按一下即可发送”。
- `stopping`：按钮暂时禁用，说明“正在整理刚才的话…”。
- `error`：恢复空闲，输入框内容保持不变，在输入区下方显示可操作提示。

## 错误处理

- 权限拒绝：不发送、不清空输入，提示用户前往系统设置开启麦克风和语音识别权限。
- 识别不可用：不发送，提示当前设备不支持并保留文字输入能力。
- 没有检测到语音：不发送，保留原输入并提示重新尝试。
- 识别服务错误或网络不可用：不发送，恢复原输入并显示简短说明。
- 系统因平台时限或长时间停顿自行结束：保留当前转写但不自动发送，恢复为空闲并提示用户检查后手动发送或重新录入。
- 页面切换、WebView 销毁或应用进入不可继续状态：取消识别，不发送。
- 重复点击、迟到结果和重复最终结果：通过会话 ID 与 `sent` 标记去重。
- 聊天发送失败：沿用现有 `submitChatInput()` 的错误展示，不由语音模块再次发送。

## 权限与隐私

- Android 声明并运行时申请录音权限；根据插件要求保留语音服务查询和必要联网声明。
- iOS 声明麦克风和语音识别用途，文案明确“用于将你的语音转换为对话文字”。
- Windows 使用系统语音识别能力，并在不可用时返回稳定错误。
- 浏览器预览只在用户点击后请求麦克风权限。
- 应用不保存原始音频，不将原始音频写入日志、数据库或项目服务器。
- WebView 桥接只接受允许来源、有效 JSON、已知消息类型和当前会话 ID。

## 测试设计

### 自动化测试

- 控制器状态：初始化、授权、监听、停止、取消和错误转换。
- 会话隔离：旧会话结果不会进入新会话。
- 自动发送：用户主动停止后发送一次；空结果、失败或取消时发送零次。
- 文本合并：空原文、有原文、中文、英文和中英文混合结果。
- 最终结果等待：停止后迟到的最终片段在 1.5 秒窗口内被纳入，超时不会重复发送。
- 桥接协议：拒绝未知类型、格式错误和来源不允许的消息。

### 页面验证

- 使用假的桥接消息验证按钮各状态、实时文本、追加规则和单次发送。
- Chrome 与 Edge 验证 Web Speech API 降级、权限拒绝和空识别结果。

### 真机验收

- Android、iOS、Windows 分别测试首次授权、已授权、拒绝权限和重新授权。
- 每个平台朗读中文、英文以及中英文混合短句。
- 验证第二次点击停止后自动发送一次，切换页面时不发送。
- Windows 原生验收前需开启开发者模式并安装 Flutter 所需的 Visual Studio C++、CMake 和 Windows SDK 组件。

## 完成标准

- 四种目标运行环境均有明确行为：Android、iOS、Windows 使用原生识别，浏览器使用降级识别或明确提示不支持。
- 用户主动停止后，识别文字正确追加并只自动发送一次。
- 所有失败和取消路径均不会误发送或丢失原输入。
- 原始音频不被应用保存或上传。
- 自动化测试通过，并完成可用平台的真实语音验收。
