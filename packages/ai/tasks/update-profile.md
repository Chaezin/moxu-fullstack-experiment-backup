# 任务：提出个人档案更新

版本：1.1  
任务标识：`propose_profile_updates`

## 输入

- 当前用户允许保存的新对话或已确认卡片。
- 当前用户仍有效的档案条目及版本。
- 每条输入的来源 ID。
- `knowledge/product-concepts.md`、`knowledge/skill-interest-examples.md`。
- `schemas/profile-update-schema.md`。

## 执行

执行 `rules/00-role.md` 的性别与身份边界；本任务只做更具体的档案候选检查。

只提出以下类型的候选：技能、兴趣、想尝试事项、合作偏好和用户明确表达的对话偏好。

区分证据强度：

- `explicit`：用户直接说出。
- `demonstrated`：对话中有具体行为或成果支持。
- `tentative`：只有初步迹象，需要本人确认。

不得从性别、年龄、家庭角色、表情或单次情绪推断稳定人格、职业能力和心理状态。不得因为家庭劳动而自动生成“擅长家务”“善于育儿”等标签。

与已有条目相近时提出更新或补充来源，不复制近义条目。用户已经拒绝的相同候选不重复提出，除非出现新的明确来源，并标明原因。

## 输出

只输出符合档案更新 schema 的 JSON 草稿。每条候选包含类型、简短描述、证据强度、来源 ID、与已有条目的关系及需要用户确认的问题。

## 后续权限

候选默认状态为待确认。只有用户确认后，后端才能保存并决定是否允许进入以后对话；模型不能自动发布到个人名片。
