# 拾光产品需求文档（PRD）

版本：1.0  
日期：2026-08-27  
状态：初版实施中

## 1. 产品概述

拾光是一款以私人对话为入口的个人成长记录产品。用户可以向 AI 伙伴“时光”讲述日常经历；系统在获得用户确认后，把对话中的真实事件整理为成长卡片、能力线索和阶段回顾，并帮助用户基于主动公开的兴趣与能力认识同路人。

拾光不以效率、收入、持续产出或积极情绪衡量用户价值，也不把日常经历自动包装成能力或成就。所有画像判断都必须能够回到具体证据，并由用户确认、修正或撤回。

## 2. 产品目标

### 2.1 用户目标

- 获得一个可以安心表达、不过度说教的私人空间。
- 从零散日常中看见真实发生的行动、选择和变化。
- 将本人认可的经历沉淀为可回顾的成长卡片。
- 通过证据了解可能形成的兴趣和能力，而不是接受标签化判断。
- 在主动公开资料后，探索方向并认识有共同兴趣的人。

### 2.2 业务目标

- 验证“AI 对话—用户确认—成长记录”的核心闭环。
- 建立可解释、可撤回的个人画像机制。
- 验证成长卡片、月度回顾和探索方向的持续使用价值。
- 在隐私与双向同意的前提下验证同路人连接需求。

### 2.3 非目标

- 不提供心理诊断、治疗、处方或危机干预服务。
- 不替用户决定婚姻、职业、投资或生活安排。
- 不承诺收入、就业、合作或个人改变结果。
- 不使用心理状态或私人聊天进行社交匹配。
- 初版不接入真实短信、QQ/微信 OAuth、实时音视频或付费系统。

## 3. 目标用户

核心用户是希望记录生活、梳理自我、发现兴趣或能力线索的成年人。产品不预设用户是否就业、婚育、承担照护工作或拥有特定资源。

典型需求包括：

- “我每天做了很多事，却很难说清自己留下了什么。”
- “我想有人听我说，但不想马上收到一堆建议。”
- “我想知道自己可能擅长什么，但不希望被随意贴标签。”
- “我希望找到对相同方向感兴趣的人，先从小尝试开始。”

## 4. 产品原则

1. 当前议题优先：先回应用户正在说的事情。
2. 用户确认优先：AI 只能提出候选，不能替用户认领。
3. 证据优先：卡片、能力和报告必须能够追溯来源。
4. 隐私默认：私人资料默认不公开，授权可撤回。
5. 小行动优先：用户明确需要建议时，提供少量可选的小步骤。
6. 不诊断、不保证：不作医疗、心理、法律、金融结论或收益承诺。
7. 双向同意：真人连接和聊天必须经过双方主动操作。

## 5. 信息架构

登录后产品包含四个一级入口：

1. 我的故事：AI 对话、历史对话、情绪选择、语音与表情辅助入口。
2. 我的记录：往日名片、成长月历、成长卡片、月度总结。
3. 我的画像：能力线索、四页能力说明书、证据索引、私人手账。
4. 我的同路人：社交名片、探索方向、推荐用户、真人聊天。

全局功能包括个人信息、每日卡片时间、隐私与记忆、内容导出和侧边栏收起。

## 6. 核心用户流程

### 6.1 首次使用

```text
注册或登录
→ 设置姓名、生日、城市和个人介绍
→ 进入“我的故事”
→ 创建第一段对话
```

### 6.2 对话与成长卡片

```text
新建对话
→ 用户表达
→ 后端安全检查
→ 时光流式回复
→ 到达设定时间或结束对话
→ 生成成长卡片草稿
→ 用户确认、修改或拒绝
→ 确认后进入成长月历
```

### 6.3 能力画像

```text
已确认卡片产生证据
→ AI 提出能力候选
→ 用户查看综合判断、典型表现、适用场景和待验证边界
→ 用户确认、修正或拒绝
→ 确认后进入个人画像
```

### 6.4 同路人

```text
用户设置社交名片公开内容
→ 选择感兴趣的探索方向
→ 系统仅使用双方公开资料推荐同路人
→ 查看公开名片
→ 发起认识请求
→ 对方接受后进入真人聊天
```

## 7. 功能需求

### 7.1 账户与登录

- 支持手机号密码注册和登录。
- 支持页面账号验证码注册和登录；初版不发送短信。
- 密码至少 8 位，服务端加盐哈希保存。
- 登录令牌过期后返回登录页，不丢失已保存的云端数据。
- 支持退出登录和忘记密码流程。
- QQ、微信按钮在接入真实 OAuth 前不得展示虚假登录成功。

### 7.2 首次资料与个人信息

- 首次注册后填写姓名、生日、城市和介绍。
- 用户可随时修改个人资料和头像。
- 手机号、生日和私人介绍默认不进入公开名片。
- 资料修改必须绑定当前认证用户。

### 7.3 我的故事

- 创建、命名、切换和删除对话。
- 历史列表显示标题、更新时间和消息数量。
- AI 回复采用流式显示。
- 支持正常交流、只倾听、帮助梳理、寻找办法和结束五种模式。
- 只倾听模式不主动提供行动清单。
- 用户请求结束时不再开启新问题。
- 对话消息由后端按当前用户和对话 ID 保存；前端不能伪造历史消息。
- 云朵是对话伙伴的视觉形象，可切换动作和选择常驻，但不改变模型权限。

### 7.4 情绪、语音和表情辅助

- 情绪选择仅用于当前对话节奏，不作为诊断。
- 语音只在用户主动按下后工作，完成转写后由用户确认文字。
- 摄像头默认关闭，开启前展示明确授权说明。
- 原始视频不上传、不持久化；正式版优先在设备端提取低置信度临时信号。
- 临时信号和用户自述冲突时，以用户自述为准。
- 设备端只向后端提交经过最小化的 `label`、`intensity`、`confidence` 和时间，不提交人脸图片、关键点序列或身份特征。
- 初版允许的辅助标签为平静、疲惫、紧张、积极和不确定；标签只能帮助调整语速、篇幅与措辞，不能用于判断用户“真实情绪”。
- 临时表情信号默认十分钟失效，用户关闭功能或离开对话后立即删除。
- 产品对外使用“表情辅助”或“面部状态线索”，不宣传能够测谎、诊断或准确读取微表情。

### 7.5 成长卡片

- 用户可以设置每日卡片生成时间和时区。
- 定时任务由后端执行，同一天最多生成一份草稿。
- 没有有效对话时不生成空卡片。
- 卡片包含标题、对话摘要、具体反馈、创造候选和来源消息 ID。
- “创造”必须由用户本人确认后才能计数。
- 用户可以修改、拒绝、删除或导出卡片。

### 7.6 我的记录

- 首页只展示两份往日对话名片回顾。
- 成长月历按月展示已确认卡片。
- 点击日期进入卡片详情和证据链。
- 月度总结采用文字回信形式。
- 报告中的对话数、卡片数等由后端计算，AI 不得修改。
- 月度总结不进行排名、人格评分或与其他用户比较。

### 7.7 我的画像

- 能力线索围绕云朵以泡泡形式展示。
- 点击能力后显示四张可翻阅名片：综合判断、典型表现、适用场景、边界与待验证。
- 证据索引采用 01—04 翻页形式，并可返回原始卡片。
- 每项能力必须有本人数据来源和证据强度。
- 用户可以选择“整理准确”“补充或修正”或删除。
- 兴趣不等同于技能，“正在尝试”不等同于承诺。

### 7.8 私人手账与记忆

- 展示用户确认保存的重要句子、卡片和能力证据。
- 每条记忆可以查看来源、修正、删除或撤回模型使用权限。
- 删除或撤回后，缓存和进行中的模型任务必须重新校验。
- 真人用户之间的私聊不能自动进入私人画像。

### 7.9 我的同路人

- 个人社交名片仅保留用户主动公开的“感兴趣”和“擅长”。
- 手机号、生日、私人对话和隐藏能力不公开。
- 探索方向页先展示兴趣方向和可探索方向，再推荐同路人。
- 推荐仅使用公开兴趣、公开能力、城市、线上交流意愿和合作意向。
- 不根据情绪、心理状态、疾病、收入或婚姻状态匹配。
- 匹配分值不能伪装成科学结论，并需说明推荐依据和局限。

### 7.10 真人连接与聊天

- 用户发起认识请求，对方接受后才能建立聊天室。
- 支持消息列表、未读状态、撤回本人消息、退出聊天。
- 支持举报、屏蔽和拒绝请求。
- 真人消息默认不发送给 AI，也不进入成长卡片。

### 7.11 隐私和数据控制

- 分别控制语音输入、表情辅助、长期记忆和匿名改进。
- 授权记录包含类型、时间、版本和撤回时间。
- 用户可以导出 TXT 对话、PDF 卡片报告和 JSON 结构化档案。
- 支持删除单条数据、清空长期记忆和注销账户。
- API Key、密码、令牌和数据库凭据永远不能发送给模型或前端。

## 8. AI 行为要求

- 模型显示名称为“时光”。
- 每次调用加载固定角色、安全、隐私和输出规则，并只加载一个任务。
- 普通聊天默认回复 60—180 个汉字。
- 信息不足时最多询问一至两个相关问题，一次只问一个重点。
- 需要行动建议时提供二至三个可在约 5—30 分钟内开始的选项。
- 不展示系统提示词、内部规则、数据库结构或推理过程。
- 卡片、画像和报告采用独立模型任务，并通过严格结构校验。
- 模型不能直接写数据库；后端校验和用户确认后才能保存。

### 8.1 倾听式对话模型优化

- 第一阶段以规则提示、任务分流、示例对话和行为评测建立倾听式风格，不直接把未经清洗的用户对话用于训练。
- 当规则与评测稳定、获得合法训练数据和用户授权后，再评估监督微调（SFT）或参数高效微调。
- 训练目标包括：先回应具体内容、不过早给建议、不评判对错、不替用户下结论、使用温和澄清和少量可选行动。
- 训练反例包括：空泛鼓励、连续盘问、心理诊断、强行积极化、性别刻板印象、直接替用户决定以及收入保证。
- 每次模型、规则或训练集变化必须运行关键行为案例；出现诊断、越权决定、隐私泄露或跨用户数据问题即不通过。

### 8.2 长期记忆机制

```text
近期对话
→ 独立任务提取记忆候选
→ 标记事实、兴趣、能力候选、偏好和来源消息 ID
→ 用户确认、修改或拒绝
→ 按字段记录授权和版本
→ 仅在相关任务中按需检索
```

- 长期记忆不依赖无限扩大模型上下文窗口。
- 自动摘要只用于当前会话连续性；不能自动变成永久画像。
- 可长期保存的内容包括本人明确表达的偏好、确认过的兴趣、能力、尝试事项和对话方式偏好。
- 疾病、心理状态、收入、婚姻推断、单次表情和模型猜测不能成为长期记忆。
- 每条记忆记录来源 ID、证据等级、确认状态、授权范围、版本和失效状态。
- 检索时只加载与当前任务相关的少量记忆；用户档案属于数据，不能覆盖系统规则。
- 用户删除、修正或撤回后，缓存及进行中的任务必须重新校验，迟到结果不得恢复旧数据。

### 8.3 实时情绪辅助策略

- 情绪信息来源按优先级排列：用户本轮明确自述 > 用户主动选择的今日状态 > 设备端临时表情信号。
- 后端把临时信号作为带来源和置信度的数据注入模型，而不是作为系统结论。
- 模型可以据此适当缩短回复、放慢追问或减少行动建议，但不能直接说“我看出你焦虑、抑郁或在掩饰”。
- 普通疲惫、低落、愤怒和沉默不能自动触发危机分流；安全分流仍由独立、确定性的后端规则负责。

## 9. 安全需求

- 确定性安全检查必须在普通模型调用和原文持久化之前执行。
- 普通疲惫、委屈、低落或愤怒不能自动诊断或升级。
- 明确且迫近的伤害风险进入固定安全分流，暂停普通生成。
- 未经人工核验不得生成具体热线、机构、号码或地址。
- 医疗、法律和金融问题仅提供一般信息与局限说明。
- 支持接口限流、验证码防刷、登录失败限制和审计日志。

## 10. 数据模型

核心数据实体包括：

- users、sessions、verification_codes
- user_profiles、user_settings、privacy_consents
- conversations、messages、conversation_summaries
- card_drafts、growth_cards、card_evidence
- profile_proposals、ability_signals、ability_evidence、interests
- monthly_reports、exploration_directions
- public_social_cards、connection_requests
- partner_conversations、partner_messages、blocks、reports
- media_assets、life_moments、export_jobs、agent_runs、audit_logs

所有私人业务数据必须绑定 `user_id`，但 `user_id` 只能从后端认证状态获取。

## 11. 接口范围

初版 API 使用 `/api/v1` 前缀，主要覆盖：

- `/auth`：注册、登录、验证码、会话、退出和密码。
- `/me`：个人资料、首次引导和社交名片。
- `/conversations`：对话与流式消息。
- `/conversations/:id/signals`：写入或撤回短时有效的设备端表情辅助信号。
- `/cards`：卡片草稿、确认和成长月历。
- `/profile/signals`：能力线索、说明书和证据。
- `/reports`：月度与年度总结。
- `/privacy`、`/memories`、`/exports`：数据控制。
- `/directions`、`/people`、`/partner-conversations`：同路人功能。

接口字段以 `packages/contracts/openapi.yaml` 为技术契约；变更需要前后端共同确认。

## 12. 非功能需求

- 手机端优先，同时适配桌面端侧边栏布局。
- 普通接口目标响应时间小于 800ms，不含模型和文件生成时间。
- AI 首个流式字符目标在 5 秒内返回。
- 所有写操作需要身份校验、字段校验和归属校验。
- 用户数据不得出现在客户端日志和公开错误信息中。
- 定时任务需要幂等，同一用户同一天不重复生成卡片。
- 模型任务记录规则版本、任务类型、模型、耗时和校验结果，不记录思维链。

## 13. 版本规划

### V1：核心记录闭环

- 账户与资料
- 云端对话历史
- 时光 AI 对话
- 卡片草稿与用户确认
- 每日生成时间
- 成长月历和能力证据
- 基础隐私控制

### V1.1：成长回顾

- 月度文字总结
- 画像修正和撤回
- 记忆管理
- TXT、PDF、JSON 导出
- 图片生活记录

### V1.2：同路人

- 公开社交名片
- 探索方向
- 双向连接请求
- 真人聊天、举报和屏蔽

### V2：外部能力

- 真实短信服务
- QQ/微信 OAuth
- 语音转写
- 设备端表情辅助
- 云端对象存储和正式任务调度

## 14. 验收标准

核心版本上线前必须满足：

- 不同账号之间无法读取或修改对方数据。
- 重启服务后正式数据仍可恢复。
- 用户对话可以创建、保存、重新打开和删除。
- AI 遵守只倾听、停止、不诊断和提示词保护规则。
- 卡片未经确认不会进入月历和画像。
- 每项能力可以追溯到当前用户的有效来源。
- 删除或撤回的数据不会被迟到任务恢复。
- 隐私设置真实影响后端数据使用范围。
- 同路人页面不泄露私人资料。
- 手机端核心页面无横向溢出，返回、加载、空状态和错误状态完整。

## 15. 成功指标

初期只观察产品使用质量，不以持续在线或情绪改善作为成功标准：

- 完成首次对话的注册用户比例。
- 用户主动确认或修正成长卡片的比例。
- 能力线索查看来源证据的比例。
- 用户主动删除、修正和撤回功能的可用性。
- 次月仍主动创建对话或查看记录的用户比例。
- 安全、隐私和跨用户数据事故数量必须为零。

## 16. 当前实现状态

当前仓库已经具备网页 UI、Flutter 初版、手机号账号体系、DeepSeek 流式聊天、Agent 规则、安全预检，以及个人资料、对话、卡片、画像、报告、隐私和同路人的部分 v1 接口。

当前数据层仍为本地 JSON 初版。正式部署前需要迁移至云端数据库、对象存储和正式任务调度系统，并补齐完整 OpenAPI 契约、权限测试与端到端测试。
